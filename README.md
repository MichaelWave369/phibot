# PhiBot

**PhiBot** is a governed micro-agent runtime and local agent-service layer inspired by Vessie / PhiVessel.

The Rung 0-7 architecture is complete. Current work is target-machine field qualification.

## Repo Steward (candidate, opt-in)

The standalone Repo Steward can survey owned public GitHub repositories for open issues and README/roadmap checkboxes. After explicit per-repository allowlisting and local credential setup, it can ask a loopback Ollama model for **one** bounded, single-file edit and open a **draft PR** for an issue labeled `phibot-ready`. It never merges, deploys, runs target-repository commands or treats a roadmap checkbox as write authorization. This is **not yet integrated** with the main Reality Gate and needs field qualification.

Run `npm run steward:scan` for a read-only inventory. See [Repo Steward setup, controls and limitations](docs/REPO_STEWARD.md) before using `steward:dry` or `steward:run`.

### PHIBOT-19: Repo Steward queue and CI verifier

Repo Steward can now skip already-attempted issue branches and move to the next eligible issue. The separate `npm run steward:verify` command checks SHA-bound GitHub Actions/check-status evidence for explicitly authorized draft PRs, including missing/failed/pending checks and stale branches. It is **read-only**, does not run tests locally, does **not** auto-merge or promote, and is not scheduled by default. See [the setup and qualifications](docs/REPO_STEWARD.md).

### PHIBOT-20: PatchBot + SkepticBot CI repair (candidate)

`npm run steward:repair:dry` can inspect an explicitly authorized PhiBot draft PR with **failed GitHub CI**, ask a local PatchBot model for a bounded repair, and have a different local SkepticBot review it. Only an explicitly enabled `steward:repair` can commit **one** repair attempt to the existing draft PR branch. It neither runs repo code nor merges, deploys or promotes any PR; the next CI run is unverified until re-inspected. This is an **isolated opt-in candidate** outside PhiBot's main Reality Gate; no background schedule is installed. See [PHIBOT-20 field and threat model](docs/CI_REPAIR_SKEPTIC.md).

### PHIBOT-21: governed GitHub RepoScout reads

Two **read-only** GitHub capabilities, `repo.steward.discover` and `repo.steward.inspect`, are now registered in PhiBot's normal `ToolExecutor` registry with registry-owned `read` authority, manifest checks, explicit repository allowlisting, fail-closed validation and ledger receipts. See [governed RepoScout setup](docs/GOVERNED_REPO_SCOUT.md) and the least-authority example manifest `bots/examples/repo-scout.phibot.json`. The existing Repo Steward draft/repair scripts are **not** brought under the Reality Gate by this rung. No background job or GitHub write is enabled.

### PHIBOT-22: exact Reality-Gated documentation draft writes

`repo.steward.draft` is a real registered `write` tool that **always** requires a signed, single-use Reality Gate grant bound to the entire proposal, even if a bot manifest says `write: true`. Its first scope is only one approved existing README/docs Markdown file on an allowlisted repo, committed to one new `phibot/issue-N` branch and opened as an unverified **draft PR**. No code edits, merging, deployment, or scheduling. The interactive `npm run steward:governed-draft -- <proposal.json>` requires operator confirmation of the exact digest and local opt-in environment settings. See [governed write guide](docs/GOVERNED_DRAFT_GATE.md).

### PHIBOT-23: human-approved governed source-code repair

`repo.steward.repair` is a **mandatory Reality-Gated** write capability for one exact replacement in an existing, still-authorized **draft PR** with verified failed CI on its pinned head SHA. Source edits are limited to permitted `src/` or `test/` files; earlier repairs, multiple-file PRs, stale heads, revoked issues, missing/pending checks and unallowlisted repositories are rejected. A real write requires a human to review the complete proposal and type the approval digest via `npm run steward:governed-repair -- <proposal.json>`. Its one commit remains **CI unverified** until new checks complete. No unattended scheduling or auto-merge is enabled. See [the governed repair field protocol](docs/GOVERNED_REPAIR_GATE.md).

### PHIBOT-24: PatchBot/SkepticBot to governed repair handoffs

`npm run steward:repair:handoff` now uses the existing dual local Ollama model prototype **only to propose and independently review** a bounded repair for an authorized failing draft PR. It saves an immutable local JSON proposal under ignored `.phibot/repo-steward/handoffs/`; `npm run steward:handoffs` lists pending local proposals and checks their shape without reading GitHub. An operator must still inspect the file and explicitly approve the exact replacement through `steward:governed-repair`. **The old `steward:repair` direct-write route is now disabled.** No automatic PR merge, repair approval or scheduling. See [the handoff workflow and Windows setup](docs/REPAIR_HANDOFF_QUEUE.md).

### PHIBOT-25: bounded read-only work queue

`npm run queue:enqueue -- <capability> '<JSON>'` accepts only the governed GitHub **read** tools `repo.steward.discover` and `repo.steward.inspect`, with an explicit owner-scoped repository allowlist. `npm run queue:run-once` invokes the existing PhiBot ToolExecutor under a read-only manifest, processes at most two attempts per invocation by default, and stores local job/lease/event evidence under ignored `.phibot/work-queue/`. `npm run queue:list` shows metadata and observation status without raw GitHub content. There are no installed timers, autonomous grants, model calls, GitHub writes, merges or deployments. See [bounded queue operations and recovery](docs/BOUNDED_WORK_QUEUE.md).

### PHIBOT-28: operator-only local queue qualification

After completing a real read-only job through the local Mission Control, run `npm run queue:qualify` in the same PhiBot clone and with the same `PHIBOT_REPO_ALLOWLIST`. It validates a completed job and its durable `ENQUEUED → LEASED → OBSERVED` transitions, checks evidence agreement, and saves one non-overwritable metadata-only SHA-256 self-report under ignored `.phibot/work-queue/qualification/`. If multiple jobs are complete, specify `-- create --job <64hex>`. A separate `verify --job <64hex>` checks the receipt's self-hash. This is **local consistency evidence, not independent remote attestation**. No network traffic, GitHub writes, model calls, or schedule is introduced. See [PHIBOT-28 Windows qualification guide](docs/LOCAL_QUEUE_FIELD_QUALIFICATION.md).


### PHIBOT-29: read-only CI Inspector eligibility preflight

`npm run queue:inspect:preflight -- --repo <allowlisted-owner/repo> --pr <number> --checks <exact-check-names>` first inspects a **real open, authorized PhiBot draft PR** and the live SHA-bound CI contexts using GitHub **GET** requests only. It rejects normal/merged PRs, revoked `phibot-ready` issues, stale branches, missing checks or moving PR heads before consuming a queue attempt. Only an explicit `--enqueue` locally records a bounded `repo.steward.inspect` job; the worker will independently recheck it when run. No GitHub writes, models, background schedule, or Reality Gate grants are added. See [CI Inspector preflight and field qualification guide](docs/CI_INSPECTOR_PREFLIGHT.md). A real eligible draft remains necessary for the field trial.
